## 5. Root Superadmin Provisioning Behavior

The provisioning script `apps/api/prisma/seed.js` was executed and tested against PostgreSQL:

1. **Phone Normalization:** Strips non-digit formatting and verifies E.164 format (`+918380989776`).
2. **Password Validation:** Enforces minimum 10 characters, at least 1 uppercase, 1 lowercase, 1 digit, and 1 symbol.
3. **Cryptographic Hashing:** Uses native `bcrypt` with cost factor 12 rounds (`$2b$12$...`).
4. **Mandatory First Login Change:** Flags `mustChangePassword = true` on initial creation.
5. **Idempotency Guarantee:**
   - First Run: Created user `2e0d6b46-3e86-4e55-9561-70edda2920bd` with `PlatformAuthorization` and bootstrap `AuditLog`.
   - Repeated Run: Detected existing record; logged `[Seed] Root Superadmin already provisioned. Password preserved; zero overwrite.` and exited with status `PRESERVED`.
6. **Zero Secrets in Logs:** Passwords, hashes, and secrets are strictly excluded from console logs, exception messages, and audit payloads.

## 9. Security Review Findings

1. **Zero Secret Leakage:** `.env` is gitignored. `.env.example` contains only non-secret placeholders.
2. **Digest Protection:** OTP challenges store keyed HMAC/salted digests (`otpDigest`), preventing lookup tables or brute force against the small six-digit space.
3. **Session Token Protection:** Database stores only `sessionTokenHash`, preventing database breach session hijacking.
4. **Invitation Token Protection:** Database stores only `tokenHash`, preventing link generation from database dumps.
5. **Tenant Isolation:** Enforced via `(tenantId, userId)` composite unique constraints and strict foreign key cascades.
